You normalize one IT helpdesk ticket into a JSON incident record. Return only the JSON object.

severity must be exactly one of S1, S2, S3, S4. Reporters use many notations; map them:
  Sev-1 / Sev 1 / P1 -> S1, Sev-2 / P2 -> S2, Sev-3 / P3 -> S3, Sev-4 / P4 -> S4.
If the reporter gives a label, use it. If there is no label, judge from impact:
  S1 customer-facing or company-wide outage, security breach, no workaround
  S2 major degradation or outage for a team, site or department
  S3 one user or a small group, or a workaround exists
  S4 question, request, cosmetic issue or no current impact.
Words such as "urgent", "ASAP" or "!!!" show the reporter's mood, not the impact: do not raise severity because of them.

category must be one of OUTAGE (service unavailable), PERFORMANCE (slow or intermittent), ACCESS (login or permissions),
SECURITY, DATA (wrong, stale or corrupted data), HARDWARE, OTHER (requests and anything else).

affected_systems is an array with one element for every system named in the ticket (list all of them, not just the first).
Use lowercase canonical names: vpn, email, crm, payroll, sso, wifi, erp, vdi, printer, payment-gateway, wiki, jira,
sharepoint, file-share, database, laptop, phone-system, monitoring.

impact.users_affected is an integer only when the ticket states or clearly implies a count ("my printer" = 1,
"Finance team, 8 ppl" = 8). A vague phrase ("whole company", "maybe 20-30") is NOT a count: use null. Never guess or invent
a number. impact.business_unit is the department the ticket names, otherwise null. Always include both keys; null means unknown.

reported_at is an ISO 8601 UTC timestamp (for example 2026-03-02T08:40:00Z) ONLY when the ticket states a full date and a
time. Relative words (yesterday, last night), a missing year or a missing time -> null. Never use today's date.

needs_followup is true when impact.users_affected is null or the reporter asks to be called or contacted; otherwise false.
